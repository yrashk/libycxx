# C++26 library specification coverage

Three audits, one per range of library clauses; each part says how to re-run it from the draft (tools/spec_audit/).

## Part 1: library, support, concepts, diagnostics, memory, metaprogramming, utilities

Audit of 2026-10-07 against the draft at eel.is (revision `c7015b48` of github.com/Eelis/draft),
GCC 16.2 and Clang 23.1. Clauses: [library] (the header tables, [compliance], [version.syn]),
[support], [concepts], [diagnostics], [mem], [meta] (with reflection, `<meta>`), [utilities].
`<charconv>` is in [text] (28.2) in this draft and `<stdckdint.h>` in [numerics]: not part of
this range.

### How to re-run

```sh
tools/spec_audit/part1/draft_tables.py --html full.html   # data/version.tsv, data/headers.tsv
tools/spec_audit/part1/inventory.py --html full.html      # data/entities.tsv
tools/spec_audit/part1/run.py [-c gcc|clang] [--summary counts.tsv] [probe...]
tools/spec_audit/part1/specifiers.py --html full.html     # constexpr/noexcept screening
```

(`full.html` is a saved https://eel.is/c++draft/full; without `--html` the scripts download it.)
`run.py` compiles everything with `-fsyntax-only` against `include/` (needs `build/<cc>` for the
generated headers) and exits 0 when nothing fails unexpectedly. Its checks:

- **headers**: every header of Tables 24, 25 ([headers]) and 47 ([support.c.headers]) compiles;
  every header of Table 27 ([compliance]) also with `-ffreestanding -fno-exceptions -fno-rtti`.
- **version**: all 313 macros of [version.syn] with the draft's value, in `<version>` and in each
  header the synopsis names (/2); the 162 freestanding ones in a freestanding `<version>`; the 19
  of /3 with `-DYCXX_HARDENED=1` and not without it (/7).
- **names**: every entity the code blocks of [support] .. [utilities] declare
  (`data/entities.tsv`, generated by `inventory.py` with `tools/gen_draft_names.py`'s tokenizer):
  a using-declaration per namespace-scope name, a derived class's using-declaration per member
  (`data/samples.tsv` gives the specialization), `#ifndef` per macro; the freestanding items
  ([freestanding.item]/4-5: the synopsis comments) again in a freestanding compilation.
- **probes**: `tools/spec_audit/part1/probes/<stable.name>.cpp`, hand-written per subclause:
  signatures and return types, `constexpr` (evaluated in `static_assert`), `noexcept`, constraints
  (a call that must be rejected, through a concept), deduction guides, and for the C++26 additions
  their basic semantics.
- Known failures are listed in `data/expected.tsv` (tables) and as `// GAP:` lines (probes), each
  naming a gap below; a known failure that no longer happens is reported (STALE / XPASS).

`specifiers.py` compares, per function name, the constexpr and noexcept overloads of the draft
with libycxx's declarations; its 14 candidates were all overload-counting noise (checked by hand
and by the probes).

### Gap list

Classes: (1) missing entity, (2) wrong shape, (3) missing or wrong behaviour, (4) feature macro,
(5) intentional (STATUS/DECISIONS), (6) blocked by the compiler, (7) draft defect.

- **P1-01 (1, 6) [ptrtag]: `pointer_tag_pair` is not implemented.** Missing: `max_pointer_bits_available`,
  `pointer_bits_available` ([ptrtag.bits]), class template `pointer_tag_pair` with its deduction
  guides ([ptrtag.pair.general]), its `tuple_size`/`tuple_element` specializations and `get`
  ([memory.syn], [ptrtag.pair.get]), and `__cpp_lib_pointer_tag_pair` (202606L, freestanding).
  STATUS lists it under "Known limitations" (`<memory>`: "no `pointer_tag_pair`"), not as a
  deliberate omission. Effort: the run-time part (tag in the low alignment bits, `tagged_pointer`
  / `from_tagged`, comparisons, tuple protocol; freestanding) is about a day with tests. The
  constructors, `from_overaligned`, `pointer()`, `tag()`, `swap` and the comparisons are constexpr
  with "Constant When: preconditions are met" ([ptrtag.pair.cons]/2, [ptrtag.pair.overalign]/1):
  in constant evaluation a tag has to live in the pointer's unused bits of a `sizeof(Ptr)` object,
  which neither GCC 16.2 nor Clang 23.1 can evaluate (no pointer-tagging builtin; Clang's
  `__builtin_align_down` cannot set bits). A conforming constexpr part is blocked on the compilers.
- **P1-02 (1) [memory.syn]: `pmr::indirect` and `pmr::polymorphic` were missing.** Fixed
  (968fb44, std module c881689); test `indirect/pmr_aliases.pass.cpp`.
- **P1-03 (2) [meta.type.synop]: `is_applicable`, `is_nothrow_applicable`, `apply_result`
  (`_v`, `_t`) were declared only through the tuple-protocol headers, not by `<type_traits>`.**
  Fixed (03628bb); test `type_traits/is_applicable_header.compile.pass.cpp`.
- **P1-04 (4) [version.syn]/2: `__cpp_lib_stdbit_h` and `__cpp_lib_stdckdint_h` were not defined
  by `<stdbit.h>` / `<stdckdint.h>`.** Fixed (6e06cc1); tests `version/header_stdbit_h`,
  `version/header_stdckdint_h`.
- **P1-05 (4) [version.syn]/5: `__cpp_lib_replaceable_contract_violation_handler` was not
  defined.** Fixed (eda75ce): 202603L with the compiler's contracts (the runtime's default
  `::handle_contract_violation` is replaceable), 0 otherwise; test
  `version/replaceable_contract_violation_handler`.
- **P1-06 (4) [version.syn]/3, /7: `__cpp_lib_hardened_shared_ptr_array` and
  `__cpp_lib_hardened_basic_stacktrace` were defined without `YCXX_HARDENED`;
  `__cpp_lib_hardened_view_interface` was missing although `view_interface::front`/`back` check
  their hardened preconditions.** Fixed (16936e8); tests `version/hardened_macros`,
  `version/hardened_macros_absent`.
- **P1-07 (3, 4) [counted.iter.*], [common.iter.*]: hardened preconditions are checked only in
  part, so `__cpp_lib_hardened_counted_iterator` / `__cpp_lib_hardened_common_iterator` (202506L)
  are not defined.** `counted_iterator` checks only its constructor (`n >= 0`); missing:
  `operator*` (/elem: `length > 0`), `operator[]` (`n < length`), `++`, `++(int)`, `+=`
  (`n <= length`), `-=` (`-n <= length`), `iter_move`, `iter_swap`
  (`include/ycxx/core/iterator_adaptors.hpp` 891-1006). `common_iterator` checks `*`, `->`, `++`;
  missing: the converting constructor and assignment (`!x.v_.valueless_by_exception()`), `==` and
  `-` (both operands not valueless), `iter_move` and `iter_swap` (`holds_alternative<I>`)
  (same file, 1083-1238). Small (an hour with death tests in `tests/ycxx/precondition`); the
  subclauses belong to [iterators], so it is left to that part of the audit to avoid conflicting
  edits.
- **P1-08 (4) [version.syn]: `__cpp_lib_view_interface` (202606L, `view_interface::at`) was not
  defined although `at` is implemented and tested.** Fixed (786142e); test
  `version/view_interface`.
- **P1-09 (6) Blocked by the compilers** (STATUS, "Known compiler gaps"; the library side is in
  place where the compiler allows it):
  - Clang 23.1: no reflection (`<meta>` empty: 260 names, `__cpp_lib_reflection`,
    `__cpp_lib_define_static`), no `__builtin_is_structural` (`is_structural`,
    `__cpp_lib_is_structural`), no contracts (`__cpp_lib_contracts`; `<contracts>` only declares),
    no throwing during constant evaluation (`__cpp_lib_constexpr_exceptions` in 7 headers), no
    `__builtin_is_pointer_interconvertible_with_class` (`__cpp_lib_is_pointer_interconvertible`;
    `is_pointer_interconvertible_with_class` and `is_corresponding_member` are declared).
  - GCC 16.2: no `__builtin_is_within_lifetime` (`__cpp_lib_is_within_lifetime`,
    `__cpp_lib_start_lifetime`); `<meta>` needs `-freflection` (without it, `<version>` does not
    define `__cpp_lib_reflection`/`__cpp_lib_define_static`; with it, all 260 `std::meta` names and
    the probe `meta.reflection.cpp` pass).
- **P1-10 (5) [expected.object.eq]: `operator==(const expected&, const T2&)` deduces its left
  operand** (STATUS, "Deliberate divergences"). Removed features (`auto_ptr`, `result_of`, ...) are
  deliberate omissions (STATUS); STATUS lists every Annex D entity as provided (not re-probed here).

No other gaps were found: every probed entity of [support], [concepts], [diagnostics], [mem]
(outside [ptrtag]), [meta] and [utilities] exists in the right header, with the probed shape, and
the C++26 additions probed (constant_wrapper, function_ref with constant_wrapper,
copyable_function, bind_front/bind_back/not_fn with a constant callable, optional<T&> and its
range support, constrained comparisons, tuple-like integer_sequence, apply with
is_applicable, exception_ptr_cast returning optional<const E&>, constexpr shared_ptr/weak_ptr,
indirect/polymorphic, owner_hash/owner_equal, type_order, the bit permutations and shifts,
`view_interface::at`, C23 `va_start`) behave as specified in constant evaluation. There are no
TODO/FIXME markers in `include/` or `src/`.

### Draft defects noticed

- [ptrtag.bits]/2 names `tagged_pointer_pair` and `tp.tagged()`; the class is `pointer_tag_pair`
  and the member `tagged_pointer()`.
- [ptrtag.pair.tagops]/3 twice names `pointer_tag_type` (meant: `pointer_tag_pair`), and /2 uses
  `ptr` and `tag`, defined nowhere (meant: `pointer()` and `tag()` of `*this`).
- [ptrtag.pair.general]: the deduction guide `pointer_tag_pair(Ptr*) -> pointer_tag_pair<Ptr*>`
  has no constructor taking a pointer alone (the constructors take `(U* p, tag_type t)`), so a
  deduction through it always fails overload resolution afterwards.

## Part 2: containers, iterators, ranges, algorithms, strings

Working draft at github.com/Eelis/draft revision `c7015b485cc3db8efaa9dfb9ff0809c5394a4ed1`
(eel.is, 2026-10-07). Where the subclauses live in this draft: [views] (`span`, `mdspan`,
`submdspan`) is in [containers]; `generator` ([coro.generator]) is in [ranges]; [numeric.ops]
(`<numeric>`, 26.10) and [specialized.algorithms] (the `<memory>` algorithms, 26.11) are in
[algorithms]; [c.strings] and [string.conversions] are in [strings].

### Method

- **Inventory.** `tools/spec_audit/extract_draft.py` reads the clauses' pages and keeps every
  synopsis and class definition outside examples and notes; `decls.py` splits them into
  declarations and `inventory.py` drops the exposition-only ones. An entity is one declaration:
  a class, a member (each overload), a free function overload, a variable or CPO, a concept, an
  alias, a deduction guide, a specialization, a `#include` of a synopsis, and each feature-test
  macro of these headers ([version.syn]) once per header that must define it and once in
  `<version>`. 6164 entities, listed with their checks in
  [`tools/spec_audit/part2/entities.tsv`](../tools/spec_audit/part2/entities.tsv).
- **Presence and shape probes**, generated by `tools/spec_audit/gen_probes.py` with
  `part2_config.py` (how each class is instantiated: `vector<int>`, `map<int, M, less<>>` with a
  transparent comparator, each view over `ref_view<vector<int>>` and a non-common `subrange`, its
  iterator and sentinel through `iterator_t`/`sentinel_t`, ...). One compile-only file per
  subclause in [`tools/spec_audit/part2/probes/`](../tools/spec_audit/part2/probes/), one line per
  check, ended by `// @E<n> <aspect>`:
  - `name`: a using-declaration of the entity (of a member: in a class derived from the
    instantiation); `header`: the same with only the synopsis's header included; `freestanding`:
    with `-ffreestanding -nostdinc`, for the names [compliance] and the `// freestanding`,
    `// mostly freestanding` and `// freestanding-deleted` marks make freestanding; `include`:
    a name of each header the synopsis `#include`s;
  - `call`: the function called with `declval` of each specified parameter type (a constructor:
    `is_constructible`; a hidden friend: through ADL; a deleted overload: `deleted`, not
    viable), `defaults`: again with the defaulted arguments left out; `ret`: the specified return
    type; `noexcept`: where the draft says `noexcept`, or its condition holds for the
    instantiation; `implicit`/`explicit`: a converting constructor's explicitness; `type`: a
    member type or alias; `guide`: what a deduction guide deduces; `spec`: a specialization is
    complete, a variable template specialization has its value;
  - a declaration with a requires-clause is checked where the instantiation satisfies it
    (`static_assert(!(constraint) || ...)`, the call in a concept so that it is a substitution
    failure); an unconstrained overload beside a constrained one of the same name and arity gets
    only `call`;
  - `macro`: each feature-test macro of the headers, in the header and in `<version>`; the
    `__cpp_lib_hardened_*` ones with `-DYCXX_HARDENED=1` (a non-hardened implementation should
    not define them, [version.syn]/7).
- **Hand-written probes** in [`tools/spec_audit/part2/manual/`](../tools/spec_audit/part2/manual/)
  (checks `// @M<n>`): the C++26 constexpr requirements (P3372 containers and adaptors, P2562
  stable sorting, P3508/P3369 specialized memory algorithms, integral `to_string`/`to_wstring`)
  and the Effects of the C++26 additions (`views::indices`, `concat`, `cache_latest`,
  `as_input`, `reserve_hint`, `ranges::to`, `find_last`, `fold_*`, `submdspan` with
  `extent_slice`/`range_slice`, `inplace_vector` `try_`/`unchecked_`, `flat_map::insert_range`,
  `subview`, ...), as constant expressions: 86 checks.
- **Semantic review.** The Effects, Returns, Throws and Hardened preconditions paragraphs of the
  C++26 additions, and every Hardened preconditions paragraph of the five clauses (52), against
  the implementation; `include/` and `src/` have no TODO, FIXME or "not implemented" marker.
- **Run:** `tools/spec_audit/run_probes.py --part part2 [-c gcc|clang] [-j2]` compiles every probe
  with `tools/ycxx-cxx` (`-fsyntax-only`) and maps each diagnostic to the check it is about;
  `tools/spec_audit/part2/gaps.tsv` lists the checks expected to fail (none now: an unlisted
  failure is FAIL, a listed check that passes XPASS). `tools/spec_audit/report.py --part part2`
  prints the tables below. **Re-run against a new draft:** `tools/spec_audit/regen.py --part
  part2` (downloads the clauses and [version.syn] into `build/spec_audit/draft/` and regenerates
  the probes), then `run_probes.py`, and review the diff of `entities.tsv`.

### How the audit works (re-run it when the draft changes)

`tools/spec_audit/part3/` (Python, no dependencies beyond the compilers):

1. `draft.py --html full.html` reads a saved https://eel.is/c++draft/full and writes
   `cache/regions.json`: every subclause of these clauses with its code blocks and item
   declarations (italics, "exposition only" and "freestanding"/"optional" comments kept as markers).
2. `gen.py` parses every synopsis code block (`decls.py`: namespaces, classes, template heads,
   access, declarations) into `inventory.tsv` (6351 declarations of the synopses, plus 14 item declarations no synopsis of these clauses repeats, `samples.EXTRA`) and writes one probe file per
   subclause, `probes/<stable.name>.cpp` (the freestanding declarations again in
   `probes/freestanding/`), with `checks.tsv` listing every check. Each check is one line:
   a concept over a dummy type, so a failure is a false `static_assert` on its own line.
   Template parameters and placeholders (`integer-type`, `floating-point-type`, `integral-type`,
   `pointer-type`) are replaced by samples (`samples.py`; every integer and floating-point type
   for the placeholders). Kinds of check:
   - presence: `using ns::name;`, or `using C::name;` in a class derived from a sample
     specialization C (members, nested classes, protected members);
   - calls: a call with arguments of the declared parameter types is valid, has the declared
     return type, is `noexcept` where declared, is valid with the defaulted arguments left out,
     and is ill-formed for a deleted function; operators as expressions, hidden friends by ADL,
     explicit object parameters, conversion functions (and `explicit`);
   - constructors: constructible (by a new-expression, so protected destructors of facets do not
     matter), nothrow where `noexcept`, not convertible where `explicit`, not constructible where
     deleted; destructors: nothrow, virtual where declared;
   - types and variables: member types and aliases name the declared type, variables and data
     members have the declared type, specializations of variable templates have the declared value
     (`enable_view<filesystem::directory_iterator>`), class specializations are complete
     (`hash`/`formatter`: enabled), base classes are public bases, enumerations are scoped with
     the declared underlying type and enumerators;
   - deduction guides: CTAD gives the declared type;
   - constexpr: every function declared `constexpr`/`consteval` is called in a constant expression
     with sample arguments (0.5 for floating-point, 1 for other arithmetic types, value-initialized
     otherwise; `spec_probe::sample`). A failure counts only when the probed function itself is not
     usable in constant evaluation; a failure inside it for the sample (a pole error, a
     precondition, a null pointer, a type without a default constructor) is "undecided";
   - macros: each `#define` of a header synopsis is defined (the `⟨N⟩` macros of `<cinttypes>`
     for N = 8, 16, 32, 64; `// optional` ones are skipped), the Annex D macros, and every
     `__cpp_lib_*` macro that [version.syn] lists for one of these headers has the specified value
     in `<version>` and in each listed header (freestanding ones also with `-ffreestanding`);
   - freestanding: the declarations marked `// freestanding` and the headers whose synopsis is
     all freestanding (`<atomic>`) compile with `-ffreestanding -nostdinc` as
     `tools/check_freestanding.sh` does;
   - [zombie.names]: with every header included, no name of Table 38 is declared in `std`
     (an ambiguity test against a program's own declaration), no name of Tables 39-40 is a macro,
     no header of Table 41 exists (informative: the names are reserved, not forbidden).
3. `run.py [-c gcc|clang] [-j N] [--filter S]` compiles every probe file (`tools/ycxx-cxx`,
   `-fsyntax-only`), maps each diagnostic to its check, and compares with `gaps.tsv` (the known
   gaps, with their class). Exit status 1 for an unlisted failure or a listed gap that passes.
   `results-<compiler>.tsv` has every check's status.
4. `report.py` writes the tables below from the last run.

What the probes do not cover: the `wchar_t` (and other) specializations beyond the first sample
(`charT` is `char`; one sample per class template); exposition-only types in a signature
(presence only, 686 declarations); `constexpr` beyond one call with sample values; behaviour
(Effects, Returns, Throws, Complexity) other than through the existing own suite, which is the
semantic part of this audit (section "Semantic gaps" below). `samples.py` lists every place where
a sample is adjusted (`FUNC`, `MEMBER_CLASS`, `CONSTRAINED`), skipped (`SKIP`, `SKIP_DECLS`,
`NO_CONSTEXPR_PROBE`) or reduced to presence (`PRESENCE_ONLY`), with the reason.
