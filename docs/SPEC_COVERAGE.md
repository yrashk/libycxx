## Part 2: containers, iterators, ranges, algorithms, strings

Working draft at github.com/Eelis/draft revision `c7015b485cc3db8efaa9dfb9ff0809c5394a4ed1`
(eel.is, 2026-10-07). Where the subclauses live in this draft: [views] (`span`, `mdspan`,
`submdspan`) is in [containers]; `generator` ([coro.generator]) is in [ranges]; [numeric.ops]
(`<numeric>`, 26.10) and [specialized.algorithms] (the `<memory>` algorithms, 26.11) are in
[algorithms]; [c.strings] and [string.conversions] are in [strings].

### Method

- **Inventory.** `tools/spec_audit/extract_draft.py` reads the clauses' pages and keeps every
  synopsis and class definition outside examples and notes; `decls.py` splits them into
  declarations and `inventory.py` drops the exposition-only ones. An entity is one declaration:
  a class, a member (each overload), a free function overload, a variable or CPO, a concept, an
  alias, a deduction guide, a specialization, a `#include` of a synopsis, and each feature-test
  macro of these headers ([version.syn]) once per header that must define it and once in
  `<version>`. 6164 entities, listed with their checks in
  [`tools/spec_audit/part2/entities.tsv`](../tools/spec_audit/part2/entities.tsv).
- **Presence and shape probes**, generated by `tools/spec_audit/gen_probes.py` with
  `part2_config.py` (how each class is instantiated: `vector<int>`, `map<int, M, less<>>` with a
  transparent comparator, each view over `ref_view<vector<int>>` and a non-common `subrange`, its
  iterator and sentinel through `iterator_t`/`sentinel_t`, ...). One compile-only file per
  subclause in [`tools/spec_audit/part2/probes/`](../tools/spec_audit/part2/probes/), one line per
  check, ended by `// @E<n> <aspect>`:
  - `name`: a using-declaration of the entity (of a member: in a class derived from the
    instantiation); `header`: the same with only the synopsis's header included; `freestanding`:
    with `-ffreestanding -nostdinc`, for the names [compliance] and the `// freestanding`,
    `// mostly freestanding` and `// freestanding-deleted` marks make freestanding; `include`:
    a name of each header the synopsis `#include`s;
  - `call`: the function called with `declval` of each specified parameter type (a constructor:
    `is_constructible`; a hidden friend: through ADL; a deleted overload: `deleted`, not
    viable), `defaults`: again with the defaulted arguments left out; `ret`: the specified return
    type; `noexcept`: where the draft says `noexcept`, or its condition holds for the
    instantiation; `implicit`/`explicit`: a converting constructor's explicitness; `type`: a
    member type or alias; `guide`: what a deduction guide deduces; `spec`: a specialization is
    complete, a variable template specialization has its value;
  - a declaration with a requires-clause is checked where the instantiation satisfies it
    (`static_assert(!(constraint) || ...)`, the call in a concept so that it is a substitution
    failure); an unconstrained overload beside a constrained one of the same name and arity gets
    only `call`;
  - `macro`: each feature-test macro of the headers, in the header and in `<version>`; the
    `__cpp_lib_hardened_*` ones with `-DYCXX_HARDENED=1` (a non-hardened implementation should
    not define them, [version.syn]/7).
- **Hand-written probes** in [`tools/spec_audit/part2/manual/`](../tools/spec_audit/part2/manual/)
  (checks `// @M<n>`): the C++26 constexpr requirements (P3372 containers and adaptors, P2562
  stable sorting, P3508/P3369 specialized memory algorithms, integral `to_string`/`to_wstring`)
  and the Effects of the C++26 additions (`views::indices`, `concat`, `cache_latest`,
  `as_input`, `reserve_hint`, `ranges::to`, `find_last`, `fold_*`, `submdspan` with
  `extent_slice`/`range_slice`, `inplace_vector` `try_`/`unchecked_`, `flat_map::insert_range`,
  `subview`, ...), as constant expressions: 66 checks.
- **Semantic review.** The Effects, Returns, Throws and Hardened preconditions paragraphs of the
  C++26 additions, and every Hardened preconditions paragraph of the five clauses (52), against
  the implementation; `include/` and `src/` have no TODO, FIXME or "not implemented" marker.
- **Run:** `tools/spec_audit/run_probes.py --part part2 [-c gcc|clang] [-j2]` compiles every probe
  with `tools/ycxx-cxx` (`-fsyntax-only`) and maps each diagnostic to the check it is about;
  `tools/spec_audit/part2/gaps.tsv` lists the checks expected to fail (none now: an unlisted
  failure is FAIL, a listed check that passes XPASS). `tools/spec_audit/report.py --part part2`
  prints the tables below. **Re-run against a new draft:** `tools/spec_audit/regen.py --part
  part2` (downloads the clauses and [version.syn] into `build/spec_audit/draft/` and regenerates
  the probes), then `run_probes.py`, and review the diff of `entities.tsv`.
